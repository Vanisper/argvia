# 命令执行契约

命令输入完成路由与解析后，处理函数负责配置组合、领域校验和业务执行。Argvia 将普通返回值、显式退出、预期失败与意外异常分别交给调用者，进程适配器据此输出和设置退出码。

## 普通业务值与显式退出

处理函数的普通返回值保留为 `{ kind: 'executed', value }`，包括数字、对象与 `undefined`。数字返回值没有退出码含义。

`@argvia/core` 提供 `exit(code)`，接受 `0..255` 的整数并返回不可变的 `ExitResult`。处理函数返回该值时，`run()` 得到：

```ts
const result = { kind: 'exit', exitCode: code, commandPath: ['java-run', 'run'] }
```

`exit` 创建返回值，不终止进程，也不抛出控制流异常。处理函数需要显式 `return`；同步返回和 Promise 解析为该值具有相同语义。外部进程的 `130`、`143` 等状态也可以通过它传递，信号监听与子进程取消由应用处理。

退出结果通过创建它的 core 实例识别。普通对象、对象展开或序列化后的副本，即使含有相同属性，也仍是普通业务数据。抛出退出结果不会触发退出协议。

非法退出码立即抛出 `RangeError`，属于调用契约错误。库不会截断、取模、解析字符串或为非法值选择默认码。

## 预期命令失败

`@argvia/core` 提供 `CommandError(message, { exitCode? })`。应用在配置或业务状态不成立时抛出它；消息必须包含非空白内容，退出码默认 `1`，可指定 `1..255` 的整数。

```ts
throw new CommandError('mainClass 必须是有效的 Java 类全名', { exitCode: 2 })
```

`run()` 只在调用处理函数的边界捕获 `CommandError`，返回：

```ts
const result = {
  kind: 'failed',
  message: 'mainClass 必须是有效的 Java 类全名',
  exitCode: 2,
  commandPath: ['java-run', 'run'],
}
```

同步抛出和异步拒绝采用相同规则。路径由执行器提供，包含隐式选择的默认命令；错误消息由应用提供，领域字段可能来自 CLI 或项目配置，不自动改写成某个 flag。

`CommandError` 必须被抛出。将它作为普通值返回时不启动失败协议。同形对象或仅有相同名称的 Error 不会被识别。空白消息抛出 `TypeError`，非法退出码抛出 `RangeError`；这两种构造失败都是开发错误。

预期业务失败独立于 `invalid-input`。后者描述路由与参数解析失败，包含解析器的诊断码；前者描述配置组合或业务操作的问题，消息可直接展示。退出码 `2` 本身不表示需要帮助，也不改变失败分类。

普通异常与其他拒绝值由 `run()` 原样拒绝。定义错误、解析器内部异常不会被转换成预期失败。

## Node 进程映射

`@argvia/node` 的 `runMain(command, options?)` 使用下表映射执行结果：

| 结果 | 输出 | 退出码 |
| --- | --- | --- |
| `executed` | 不自动输出业务值 | `0` |
| `help` | stdout 输出帮助 | `0` |
| `invalid-input` | stderr 输出诊断与对应命令的帮助提示 | `2` |
| `exit` | 无附加输出 | 指定退出码 |
| `failed` | stderr 输出 `命令路径: 消息` | 指定退出码 |
| 意外异常 | stderr 输出异常消息或拒绝值的字符串形式 | `1` |

进程适配器设置 `process.exitCode`，不调用 `process.exit()`。应用需要保留业务退出状态时使用显式退出协议；处理函数自行修改 `process.exitCode` 不属于结果协议。业务已经输出的日志不由适配器重放。

应用可通过 `{ debug: true }` 让意外 `Error` 输出非空堆栈，缺失或为空时回退消息。其他拒绝值、预期失败及各分支退出码保持表中映射。调试默认关闭，由应用显式传入，详细规则见[帮助与诊断契约](help-contract.md)。

## java-run 领域与验证

用于配置读取的目录先完成非空白校验，无效时不调用配置服务。`run`、`plan` 在读取项目配置并完成覆盖后校验其余领域值；`init` 只验证本次输入与应用默认值。领域校验失败不会调用启动、计划或初始化服务。

样本校验 Java 主类名、单模块选择器以及目录、工具路径、JVM 与构建参数的非空白约束。应用参数与透传值保留空字符串、空白及 token 边界。帮助与解析失败发生在配置读取和领域校验之前。

启动服务返回数字状态，命令处理函数通过 `exit(await launch(request))` 显式适配；计划与初始化仍可返回业务数据。演示入口使用内存配置与输出请求的服务，集成测试注入返回非零状态的启动服务，通过真实 Node 子进程验证退出状态。样本不启动 Java、不写项目配置，也不引入测试专用 CLI 选项。

运行时、严格类型检查及独立产物消费共同验证：有效与非法退出码、普通值不误判、同步与异步结果、默认与嵌套命令路径、预期与意外失败，以及 Node 的输出和退出码。
