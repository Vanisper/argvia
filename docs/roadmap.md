# 开发顺序

## 工程初始化

已完成 Vite+ monorepo、两个 private 包、工作区依赖、类型配置、库打包与 CI。工程约定已对照实际 `vp create` 生成结果。

## 统一行为契约

第一轮已确定并实现 [解析契约](../packages/parser/docs/contract.md)，覆盖输入归属、默认值、重复、贪婪消费、来源及错误优先级。原始 [算法规范](../packages/parser/docs/algorithm.md) 已纳入包内文档，明确标注当前行为的调整。

## 解析与核心组合

parser 的独立使用和 `prepare → complete` 流程已实现；准备结果与完整输入保持类型区分。第二轮 core 建立单命令模型、命名位置参数与类型化 handler，以 jar 入口、main 入口两个独立应用案例验证组合边界。

帮助与版本依据真实绑定结果处理，帮助优先于版本，并在完整性与位置值检查之前返回。其他选项输入错误仍即时报告。一次 `execute` 只解析一次；`parse` 是不执行 handler 的独立使用入口。

## 完整调用流程

下一轮先评估命令树、子命令作用域和共享选项的路由规则，再补齐命令级约束。依据实际运行入口评估输出、取消、清理和宿主适配；不预设独立 node 包。

## 使用体验与配套能力

以可运行场景比较现有模块写法和候选语法，验证补全、类型、复用与组合体验。

配置、进程、日志、终端和交互在实际需求出现后逐项评估。Java/Maven/Gradle 等业务规则继续归应用。
