# 开发顺序

## 工程初始化

Vite+ monorepo、两个 private 空包、工作区依赖、严格类型配置、库打包与 CI 构成本轮基线。源码入口仅为空导出，不代表解析或命令能力已经迁移。

## 统一行为契约

对照历史原型和参数解析规范，确定输入归属、默认值、重复、布尔值、来源及错误优先级。通过真实 CLI 用例决定所需能力。

## 解析与核心组合

先验证 parser 的独立使用及可组合过程，再建立 core 的命令模型、命名位置参数和类型化输入。准备结果与完整输入保持类型区分。

帮助与版本依据真实绑定结果处理。避免原始字符串预扫描，以及为了检查帮助和执行而重复完整解析。

## 完整调用流程

补齐命令组织、帮助、执行约束、业务调用和运行结果。用实际入口确定输出、取消、清理和宿主适配的位置；不预设独立 node 包。

## 使用体验与配套能力

以可运行场景比较现有模块写法和候选语法，验证补全、类型、复用与组合体验。

配置、进程、日志、终端和交互在实际需求出现后逐项评估。Java/Maven/Gradle 等业务规则继续归应用。
