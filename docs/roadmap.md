# 后续验收方向

当前基础包括独立 parser、命令树与显式路由、只读定义描述，以及准备、完成和执行阶段。新增能力围绕同一模型验证，包继续保持 private。

## 持续验证

维护覆盖以下边界的行为与类型测试：

- 选项归属、默认值、重复、贪婪消费和来源记录。
- 嵌套路径、节点本地作用域、终止符与原始坐标。
- 定义快照、共享声明、节点重复组合和调用状态隔离。
- 准备态到完整输入的类型收窄，以及同步、异步 handler 返回值。
- 回调、输入错误与程序异常的区别；完成结果复用不重复解析。
- 应用使用普通选项和描述模型实现控制逻辑，不依赖核心内建名称。

`vp run ready` 是源码检查、测试和构建入口。包消费还需使用实际打包文件，在独立项目验证 JS 导入和声明消费，避免仅由工作区源码验证推断发布产物可用。

## 应用组合

[`playground`](../playground/README.md) 集中保存通过公开接口构建的应用及其测试。[Workspace 示例](../playground/workspace/README.md) 覆盖多级命令、声明复用、帮助与版本响应以及服务注入。

通过不同类型的 CLI 场景检验定义模型与阶段边界，例如项目工具、检查命令、包装器和脚手架。场景应覆盖共享声明、自定义值协议、原样尾部参数和应用配置覆盖。

业务形态可以随新模型调整。领域配置、进程启动和业务重命名由应用组织，不将某个既有应用的接口固化为核心约束。

## 展示与增强能力

帮助、版本和文档生成可由应用消费公开定义与调用阶段。只有出现稳定的复用需求时，再形成便捷工具或增强包。

验收重点是结构化内容是否足够、字段说明是否明确、定义与解析是否一致，以及增强能力能否只依赖公开接口。新增展示元数据应由声明提供，不能通过执行解析器推断值域。

## 宿主边界

以实际运行入口验证 I/O、诊断、退出状态、取消和资源清理。数字 handler 返回值继续是业务数据；退出策略由宿主显式决定。

发布为应用内组合、子入口或独立包，应有消费方式、运行平台和依赖证据。普通 parser/core 入口继续保持宿主无关。

## 定义体验

以普通对象与共享声明为基线，评估便捷构造器或链式表达。比较补全、错误定位、重复声明、跨模块复用和类型保真。候选语法共用当前定义与执行模型，不增加另一套解析行为。
