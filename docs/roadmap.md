# 开发顺序

## 工程初始化

已完成 Vite+ monorepo、两个 private 包、工作区依赖、类型配置、库打包与 CI。工程约定已对照实际 `vp create` 生成结果。

## 统一行为契约

第一轮已确定并实现 [解析契约](parser-contract.md)，覆盖输入归属、默认值、重复、贪婪消费、来源及错误优先级。规范测试和独立使用示例验证这些行为，不沿用历史包的兼容承诺。

## 解析与核心组合

parser 的独立使用和 `prepare → complete` 流程已实现；准备结果与完整输入保持类型区分。下一轮建立 core 的最小命令模型、命名位置参数和类型化输入，用真实命令验证组合边界。

帮助与版本依据真实绑定结果处理。当前准备流程只延期必填检查，其他输入错误仍即时报告；core 的产品策略需另行设计。避免原始字符串预扫描，以及为了检查帮助和执行而重复完整解析。

## 完整调用流程

补齐命令组织、帮助、执行约束、业务调用和运行结果。用实际入口确定输出、取消、清理和宿主适配的位置；不预设独立 node 包。

## 使用体验与配套能力

以可运行场景比较现有模块写法和候选语法，验证补全、类型、复用与组合体验。

配置、进程、日志、终端和交互在实际需求出现后逐项评估。Java/Maven/Gradle 等业务规则继续归应用。
