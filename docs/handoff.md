## 已确认的接口方向

1. 无默认值的可选单值选项，省略时得到 `undefined`，包括布尔选项。应用合并配置后设置最终默认值。
2. 不需要参与配置覆盖的开关可显式声明 `{ default: false }`，处理函数中得到 `boolean`。
3. `force` 属于 `init` 的局部选项，不能进入 `run`、`plan` 的输入类型或帮助。
4. 一份命令定义贯通解析、校验、帮助和处理函数类型；共享选项通过普通对象复用。
5. Monorepo 指 Argvia 与配套包。起步采用一个命令定义发布包、多入口及真实使用样本；配套包按独立职责逐步形成。

命令对象与类型化参数构造器是当前工作候选；函数名、完整组合规则与导出路径尚未冻结。

## 当前成果与验证边界

先阅读 [设计草案](design.md)、[java-run 场景分析](java-run-case-study.md)、[运行实验记录](command-api-experiment.md)。

`experiments/command-api/` 是第一轮可运行实验，包含：

- 字符串位置参数，字符串、数值、枚举和布尔选项
- 默认值、必填规则、分组与叶子命令、共享定义的类型推导
- 显式 `argv` 的 `run` 与接入进程的 `runMain`
- 帮助、结构化输入错误、业务异常与退出码处理
- 定义快照和描述器检查，避免调用方修改定义后让静态类型与实际值不一致

`run` 的业务返回值当前为 `unknown`；`runMain` 不把普通数值返回值自动当作退出码。业务异常在 `run` 中原样传播，终端入口再设置退出码。

实验的 `index.ts` 同时导出 `runMain`，因此会连带导入 `node:process`。建立正式入口时需要检查依赖关系，让显式 `argv` 的核心入口与进程适配入口分别导出。

第一轮实验的 `option.boolean()` 仍在省略时得到 `false`，这与用户后来选定的契约存在明确差异，应该作为接手后的第一个修正。不要把旧实现当作已确认的最终规则。

`docs/prototypes/java-run-definition.ts` 是第二轮声明实验，验证局部 `force`、字段拼写映射、重复数组、条件透传上下文、默认命令键约束及配置合并类型。其中 `flag`、`multiple`、`passthrough`、`defaultCommand` 尚未接入第一轮运行时。验证函数没有执行，不能据此声称完成 java-run 集成。

交接前运行 `pnpm check`：lint、严格 TypeScript 检查通过，2 个测试文件中的 59 个运行时测试通过。项目使用 pnpm 10.33.2，当前工具链曾在 Node.js 22.22.2 下验证；依赖由锁文件固定。

## 最小可开始实施的范围

建议按以下顺序直接推进，每个阶段形成可复查的小提交：

1. 修正实验中的布尔缺省契约，支持显式布尔默认值；同时验证类型与运行时，并覆盖“CLI 未输入时保留配置文件 true”的场景。
2. 建立 monorepo 的最小布局：`packages/argvia/`、`playground/`、`docs/`。将验证过的核心能力转入包内，保留实验记录。根目录和未准备发布的包保持 `private`。
3. 明确核心入口与进程入口的契约，验证包导出、类型声明与构建产物可被真实消费。`argvia` 和 `argvia/node` 是当前入口候选，需检查 Node 与 Bun 的适用边界。
4. 用 java-run 的 `run`、`plan`、`init` 场景逐项实现字段映射、重复参数、透传与默认命令。每项先记录解析规则，再用行为和类型验证共同支持接口。

第一阶段与最小包布局已有足够依据开始。正式实施不要求一次冻结所有接口，后续取舍随证据收敛。应用配置、Java 构建和进程调度仍属于样本业务。

## 尚未冻结的选择

- 默认命令如何处理未知命令词，以及是否允许 `--force init` 这样的前置选项
- 帮助是否覆盖未知选项与缺值错误；帮助必须跳过业务配置读取、项目准备和必填检查
- 以负号开头的值如何传递；当前实验会把 `--main --help` 中的后者作为字符串值
- 重复选项的默认集合、空值规则、否定布尔、别名和缺省 CLI 拼写
- 领域转换与校验接口、业务退出结果、取消信号、处理函数返回值推导
- Node / Bun 的支持范围，以及配套包独立拆分时机

`java-run` 自身也有需要改进的定义组织。它已经在解析后拒绝非 `init` 的 `force`，所以这里改善的是定义、类型和帮助的作用域。`plan` 同样支持 `--` 透传，并在预览中展示应用参数，不应在改写样本时丢失。

参考项目配置合并的顺序是配置标量被显式 CLI 值覆盖，配置数组后追加 CLI 数组，应用参数最后追加透传数组。`init` 跳过旧配置读取。业务退出码与取消码需要原样保留。
