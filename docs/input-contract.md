# 命令输入契约

一份命令定义决定选项拼写、解析结果、帮助和处理函数上下文。本文规定字段映射、布尔取值、重复字符串、原样透传与默认命令的组合规则；实施状态见[架构与开发边界](design.md#实施顺序)，已经可用的接口见 [API 文档](api.md)。

## 字段与选项拼写

`flag` 指定一个长选项拼写，例如 `buildTool: option.enum(['maven', 'gradle'], { flag: '--tool' })`。用户输入 `--tool=maven`，处理函数读取 `options.buildTool`。

- 未指定 `flag` 时，使用 `--` 加对象键，不自动转换大小写
- 指定 `flag` 后替换默认拼写，对象键不再作为隐式别名
- 拼写以 `--` 和字母开头，后续只允许字母、数字、下划线和连字符
- 同一命令中的有效拼写必须唯一，`--help` 保留给内置帮助
- 位置参数不接受 `flag`，不同子命令可以复用同一拼写

定义阶段保存拼写映射的快照。解析、帮助和错误提示共用该映射，结果始终按定义的字段键组织。

## 显式布尔值

布尔选项通过等号接受精确的小写 `true` 或 `false`。裸开关得到 `true`；省略时使用描述器默认值，没有默认值则得到 `undefined`。

| 输入 | 结果 |
| --- | --- |
| `--include-tests` | `true` |
| `--include-tests=true` | `true` |
| `--include-tests=false` | `false` |
| `--include-tests false` | 开关为 `true`，下一项仍作为位置参数处理 |
| `--include-tests=`、`--include-tests=0`、`--include-tests=False` | 无效取值 |
| `--no-include-tests` | 未单独声明该拼写时为未知选项 |

布尔选项不消费下一项，不裁剪值中的空白，不接受其他大小写或数值缩写。裸开关与等号形式属于同一字段，任意重复组合都沿用标量重复错误；显式 `flag` 决定诊断中的拼写。

帮助显示 `[=true|false]`。帮助优先级和 `--` 边界保持一致：`--include-tests=bad --help` 展示帮助，透传尾部中的布尔拼写保持原样。CLI 的 `false` 参与 `??` 配置覆盖，可以关闭项目配置中的 `true`。

## 重复字符串

`option.string({ multiple: true })` 每次出现消费一个字符串，并按该字段的输入顺序得到 `string[]`。未输入时得到新建的空数组；单值选项仍拒绝重复输入。

```ts
const options = {
  jvmArgs: option.string({ flag: '--jvm-arg', multiple: true }),
  applicationArgs: option.string({ flag: '--arg', multiple: true }),
}
```

`--jvm-arg=-Dname=a=b --jvm-arg=-Xmx1g` 得到 `['-Dname=a=b', '-Xmx1g']`。只按第一个等号分离选项和值，不重新拆分字符串中的空白或逗号；空字符串沿用普通字符串规则。

首版仅支持重复字符串，不接受 `required` 或 `default`。空数组表示本次没有追加项，不表示清空配置；配置读取、数组追加和替换策略由应用决定。每次执行使用独立数组，处理函数对结果的修改不会影响后续执行。

## 原样透传

叶子命令声明 `passthrough: true` 后，处理函数额外获得 `passthrough: readonly string[]`。首个独立的 `--` 结束当前命令的参数解析，其后的 token 全部进入该数组。

- 分隔符本身不进入数组，后续的第二个 `--` 保留
- 空字符串、空白、等号、帮助标记、未知选项和命令词都原样保留
- 不再解释引号、转义或 shell 语法，输入以调用者传入的 argv 边界为准
- 分隔符之前的位置参数仍按定义匹配并检查必填，尾部不能补足它们
- 没有分隔符时提供空数组；未启用透传时上下文没有该字段，`--` 后仍按普通位置参数匹配

透传不会放宽分隔符前的输入校验，也不会自动并入某个业务字段。分组不声明透传，具体叶子命令决定如何接收尾部。

## 默认子命令

分组通过 `defaultCommand: 'run'` 指向 `commands` 中已有的键。类型约束静态键，定义校验确认目标实际存在；目标可以是叶子或另一个分组，沿用相同路由规则。

| 分组收到的首项 | 选择规则 |
| --- | --- |
| `-h`、`--help` | 显示当前分组帮助 |
| 已注册的命令词 | 消费该词并进入对应子命令 |
| 没有输入 | 有默认命令则进入默认命令，否则显示分组帮助 |
| 以 `-` 开头的输入，包括独立 `--` | 有默认命令则原样交给默认命令，否则返回未知选项错误 |
| 未知裸词 | 返回未知命令错误 |

默认选择不插入或改写 argv，也不向后寻找命令词。选中叶子后，剩余输入使用同一套参数规则。`--cwd plan` 中的 `plan` 是字符串值；`--cwd project plan` 不会重新选择 `plan` 子命令，有无位置参数决定末尾 token 是否有效。

未设置默认命令时，显式命令路径必须位于分隔符之前，例如 `tool run -- tail`。分组不消费 `--`，该分隔符由选中的叶子解释。

默认叶子的首个裸位置参数可通过显式子命令消歧。未启用透传时也可以用 `--`；开启透传后 `--` 专用于尾部。诊断与叶子帮助采用包含默认子命令的完整路径。分组帮助说明默认命令及其帮助入口。

## 帮助与取值边界

合法命令路径中的帮助优先于输入值校验、必填检查和业务执行，未知子命令仍报错。帮助与正式解析共用 token 消费规则：

| 输入 | 结果 |
| --- | --- |
| `--main --help` | 字符串选项的值为 `--help` |
| `--main=--help` | 字符串选项的值为 `--help` |
| `--main=x --help` | 显示已选命令的帮助 |
| `--unknown --help` | 在合法命令路径上显示帮助 |
| `--main -- --help` | `--main` 缺值，尾部标记不触发帮助 |
| `-- --help` | 开启透传时作为尾部，未开启时作为位置参数 |

字符串可以消费以负号开头的下一项，但独立的 `--` 永远作为分隔符；需要该字符串值时使用 `--main=--`。数值、枚举和布尔沿用各自的输入校验。业务配置读取与副作用只发生在完成解析、校验后调用的处理函数中。

## java-run 组合验收

| 命令 | 配置读取 | 数组组合 | 局部选项 |
| --- | --- | --- | --- |
| `run`，包括默认选择 | 读取选定目录的项目配置 | 配置数组后追加 CLI 数组，应用参数最后追加透传数组 | 不接受 `force` |
| `plan` | 与 `run` 相同 | 与 `run` 相同，交给计划服务 | 不接受 `force` |
| `init` | 跳过旧配置 | 只保存本次 CLI 数组及应用透传数组 | `force` 缺省为 `false` |

标量按显式 CLI、项目配置、应用默认值的顺序选择。数组合并不修改配置或输入数组。三种命令的帮助与输入失败均不得调用配置服务或业务服务；透传尾部中的 `--help` 属于应用参数。

验证同时覆盖类型推导、运行结果、帮助与错误、重复执行隔离，以及构建产物在独立消费者中的使用。
