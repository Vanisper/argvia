# CLI 选项与参数解析规范

本规范定义基于选项规格的 CLI 参数解析行为，供解析器实现者、选项规格作者和测试维护者使用。解析器接收字符串数组 `argv`，识别选项与位置参数，绑定并解析选项值，按默认值和重复策略生成结果。

解析核心依据选项规格工作，不内置业务语义。合法值集合由值解析器提供；帮助显示、版本输出、命令执行和运行环境检查由调用方负责。

## 1 范围与约定

### 1.1 输入边界

`argv` 只包含需要解析的参数，不包含程序名、解释器路径或脚本路径。调用方必须先剔除这些内容。

解析器不处理 shell 命令文本，不重新进行空白分词、引号剥离、转义或变量展开。每个数组元素已经是一个参数单元；空字符串也是有效的参数单元。例如，命令行中的 `--name ""` 通常对应 `["--name", ""]`，双引号本身不属于值。

### 1.2 规范用语

“必须”和“不得”表示一致性要求；“应”表示推荐做法；“可以”表示允许的实现选择。表格中的结果与正文规则具有相同约束力。伪代码用于说明这些规则，不规定实现语言和内部数据结构。

## 2 术语与职责

### 2.1 术语

| 术语               | 含义                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 参数序列 `argv`    | 调用方提供的字符串数组                                             |
| 参数单元 `token`   | `argv` 中的一个元素，可能包含选项、显式值或多个短选项              |
| 选项               | 由一份 `OptionSpec<T>` 声明的逻辑选项，具有长名和可选的短名        |
| 选项出现           | 输入中对某个选项的一次显式指定；短选项簇的每个成员分别计为一次出现 |
| 位置参数           | 未被识别为选项、也未被消费为选项值的参数单元                       |
| 原始值 `raw`       | 从输入中取得、尚未归一化和解析的值字符串                           |
| 解析值             | 原始值经值解析器处理后得到的 `T`                                   |
| 结果值             | 经过重复归约和默认值处理后向调用方提供的值                         |
| 待值状态 `pending` | 已识别一次选项出现，尚未确定其值的扫描状态                         |
| 消费               | 将参数单元接收为当前选项的值，并使其不再进入常规识别流程           |
| 裸用默认值         | `defaultWhenBare`，某次出现未绑定显式值时使用的值                  |
| 缺席默认值         | `defaultWhenAbsent`，整个选项未出现时使用的值                      |
| 结算               | 结束尚未取得值的待值状态：使用裸用默认值，或报告缺值               |
| 显式绑定           | 通过 `--key=value` 或适用的短选项粘连形式，在同一参数单元中指定值  |

选项整体分为**未出现**与**已出现**。某次出现又分为**裸出现**与**带值出现**。允许重复时，一个选项可以同时包含裸出现和带值出现，不能把 `absent`、`bare`、`valued` 当作整个选项的三个互斥状态。

布尔值是一种值类型；旗标描述无需分离值即可使用的选项行为。设置裸用默认值的选项不限于布尔类型，例如 `--color` 可以裸用时取 `always`，`--verbose` 可以裸用时取整数 `1`。

### 2.2 职责边界

| 职责         | 负责内容                                                     | 失败类别       |
| ------------ | ------------------------------------------------------------ | -------------- |
| 解析机制     | 识别选项、绑定值、管理状态、处理默认值和重复策略、检查必填项 | 命令行用法错误 |
| 值解析与校验 | 归一化、类型转换、值域检查以及跨选项约束检查                 | 命令行用法错误 |
| 业务处理     | 根据解析结果和运行环境判断能否执行，并执行操作               | 执行期错误     |

值解析可以在扫描过程中调用，分层不要求分成多遍处理。扫描器可以根据解析成功或失败决定是否消费参数单元，但不得内置具体枚举成员或业务条件。跨选项约束在扫描完成后由校验组件检查。

## 3 选项规格与配置

### 3.1 接口模型

以下类型约定用于说明接口语义。`ParseResult` 通过 `ok` 区分成功与失败，成功值可以是 `false`、`0` 或空字符串。

```ts
type ParseResult<T> = { ok: true; value: T } | { ok: false; expected: string; reason?: string };

type ValueParser<T> = {
  normalize?: (raw: string) => string;
  parse: (normalized: string) => ParseResult<T>;
};

type ParseConfig = {
  greedy?: boolean; // 默认 false，适用于整个参数序列
};

type OptionSpec<T> = {
  long: string;
  short?: string;
  parse: ValueParser<T>;
  defaultWhenBare?: T;
  defaultWhenAbsent?: T;
  required?: boolean; // 默认 false
  repeat?: "last" | "append" | "error"; // 默认 "last"
};
```

`long` 和 `short` 只填写名称，不包含前缀 `--` 或 `-`。同一规格的长名和短名指向同一选项，共享出现记录、必填检查和重复策略。规范长名作为结果中的选项标识。

默认值是否设置必须依据字段存在性判断，不得使用真值判断。`defaultWhenBare=false`、`0` 和 `""` 都表示已设置裸用默认值。实现可以使用专用哨兵表示未设置。

### 3.2 构建期校验

注册选项时必须拒绝以下配置，并报告选项规格错误，不得归类为用户输入错误：

- 长名为空、包含 `=` 或以 `-` 开头。
- 短名不是恰好一个 Unicode 码点，或短名为 `-`。短选项扫描也必须按码点进行。
- 长名之间重名，或短名之间重名。
- `required=true` 且设置了 `defaultWhenAbsent`。这是本规范对配置的限制。
- `repeat` 不属于 `last`、`append`、`error`，或值解析器必需的 `parse` 方法不是可调用函数。

选项名大小写敏感，必须按原样查表，不进行隐式归一化。`normalize` 仅处理值。需要别名时，扩展注册模型必须保证别名仍指向同一逻辑选项；本接口直接支持一长名和一短名。

数字可以被显式注册为短名；未注册的数字不具有特殊选项语义。

### 3.3 默认值的合法性

默认值已经是 `T`，不得重新当作原始字符串传入 `parse`。选项规格作者必须保证默认值满足该选项的值域约束；静态类型 `T` 本身不保证整数范围、枚举成员或其他运行期条件。

解析器只执行规格声明的默认值规则。裸用默认值的存在性还参与分离式消费和短选项簇的扫描决策，不能把它描述成仅在收尾时填值的字段。

## 4 支持的语法

### 4.1 绑定形式

| 形式           | 解释                                                           |
| -------------- | -------------------------------------------------------------- |
| `--name=value` | 在第一个 `=` 处分割名称与值；右侧整串为原始值，包括空串        |
| `--name value` | 长选项进入待值状态，按消费规则判断下一参数单元                 |
| `-n value`     | 短选项处于参数单元末尾时进入待值状态，与长选项使用相同消费规则 |
| `-nvalue`      | 仅当 `n` 未设置裸用默认值时，将余串整体作为其值                |
| `-abc`         | 按短选项扫描规则逐个解释；某个选项取得余串为值后停止扫描       |

`--name=a=b` 的值是 `a=b`；`--name a=b` 中的 `a=b` 也作为完整值处理。

短选项粘连不把 `=` 当分隔符。`-c5` 的值是 `5`；`-c=5` 的值是 `=5`，整数解析器应拒绝后者。不得为了与长选项对齐而剥离这个 `=`。

显式绑定不进入待值状态，该次出现取得一个值后立即结束；即使 `greedy=true` 且 `repeat=append`，也不继续接收下一参数单元。显式值解析失败必须报告 `InvalidValue`，不得退回裸用默认值。

### 4.2 短选项簇与粘连

对以单个 `-` 开头、且不是独立 `-` 的参数单元，从前缀后的第一个码点起扫描。每识别一个短名，就开始一次选项出现：

| 当前短选项       | 是否还有余串 | 行为                                             |
| ---------------- | ------------ | ------------------------------------------------ |
| 未注册           | 任意         | 报告 `UnknownOption`                             |
| 已设置裸用默认值 | 有           | 本次出现使用裸用默认值，继续将余串作为短选项扫描 |
| 已设置裸用默认值 | 无           | 进入待值状态，按全局消费规则处理后续输入         |
| 未设置裸用默认值 | 有           | 将余串整体作为显式值，结束本参数单元的扫描       |
| 未设置裸用默认值 | 无           | 进入待值状态，结束本参数单元的扫描               |

例如，`h` 和 `v` 均已注册且有裸用默认值 `true`，`c` 为无裸用默认值的整数选项：

- `-vc5` 表示 `v=true`、`c=5`。
- `-v5` 将 `5` 解释为另一个短名；如果未注册 `5`，报告未知选项，不尝试把 `5` 解析为 `v` 的值。
- `-v false` 在默认配置下得到 `v=true` 和位置参数 `false`；在 `greedy=true` 下可以得到 `v=false`。
- `-hvc 5` 中，`h` 和 `v` 使用裸用默认值，`c` 从下一参数单元取值。

簇内取得粘连值的选项至多一个。它之后的所有字符属于值，所以“取值选项位于簇末尾”是扫描规则的结果，不是额外的格式检查。`-c5x` 的候选值是 `5x`，不会再尝试识别 `x`。

### 4.3 独立短横线与终止符

独立的 `-` 不表示选项。在待值状态下，它可以被值解析器接收；其他情况下，它是位置参数。将其用于标准输入是调用方的约定。

**独立参数单元 `--` 是选项终止符，不得被消费为分离式值。** 若存在待值选项，先结算；结算成功后，其余参数单元全部作为位置参数，不再识别任何选项。终止符本身不进入结果。

显式值中的 `--` 是普通字符串。例如，`--name=--` 的值是 `--`；`-n--` 在 `n` 未设置裸用默认值时，其值同样是 `--`。

## 5 扫描与消费规则

### 5.1 已注册选项的识别

消费判断必须使用以下识别规则：

1. 参数单元以 `--` 开头且不是独立 `--`：取前缀之后、第一个 `=` 之前的名称；长名已注册则视为已注册选项。
2. 参数单元以单个 `-` 开头且不是独立 `-`：其第一个短名已注册，则视为已注册选项。
3. 其余情况不视为已注册选项。

这一步不验证整个短选项簇，也不验证显式值。例如，已注册 `v` 时，`-vZ` 会先阻止前一个选项消费它；随后进入常规识别时，才可能因 `Z` 未注册而报错。

“不视为已注册选项”不等于“一定是位置参数”。该参数单元仍可能被待值选项消费；如果回到常规识别且具有选项形态，则可能报告未知选项。

### 5.2 参数单元的处理顺序

解析器在参数序列上单向扫描，最多保留一个待值选项。每个参数单元先处理已有待值状态。若没有被消费，再执行常规识别：独立 `--`、长选项、短选项、位置参数。遇到位置参数不会停止后续选项识别。

因此，`a.txt --version` 中的 `--version` 仍按注册表识别。解析结果保留位置参数的输入顺序；调用方若限制选项与位置参数的交错方式，需要依据出现位置进行后续检查。

### 5.3 尚未取得值的待值状态

按以下顺序处理当前参数单元 `t`：

1. `t` 为独立 `--` 或已注册选项：结算当前待值选项；成功后重新处理 `t`。
2. `greedy=false` 且已设置裸用默认值：结算为裸用默认值，不调用值解析器；重新处理 `t`。
3. 其余情况尝试值解析。成功则消费 `t`；失败且有裸用默认值，则结算并重新处理 `t`；失败且无裸用默认值，则报告 `InvalidValue`。

到达输入末尾仍处于待值状态时，也执行结算。结算只负责“取裸用默认值或报告 `MissingValue`”，不负责分配位置参数。

上述规则使已注册选项优先于分离式值。没有裸用默认值时，遇到另一个已注册选项属于缺值，遇到普通但无法解析的候选值属于值非法。

### 5.4 贪婪消费

`greedy` 控制分离式值的消费方式；`repeat` 同时约束一次出现可取得的值数量，并决定多次出现后的归约方式。

| 选项配置                        | `greedy=false`                     | `greedy=true`                            |
| ------------------------------- | ---------------------------------- | ---------------------------------------- |
| 有裸用默认值，`last` 或 `error` | 不消费下一参数单元，使用裸用默认值 | 尝试取得一个分离值，失败时按待值规则处理 |
| 无裸用默认值，`last` 或 `error` | 尝试取得一个分离值                 | 尝试取得一个分离值                       |
| 有裸用默认值，`append`          | 不消费下一参数单元，追加裸用默认值 | 尝试取得首值，成功后继续接收可解析值     |
| 无裸用默认值，`append`          | 尝试取得一个分离值                 | 尝试取得首值，成功后继续接收可解析值     |

只有 `repeat=append` 且 `greedy=true` 时，取得首个分离值后才继续消费。后续遇到独立 `--`、已注册选项或无法解析的参数单元时，结束本次出现，将该参数单元交回常规识别。此时已经取得值，不再补裸用默认值，也不因停止追加而报告 `InvalidValue`。

这使首值与后续候选值有不同的失败行为。以整数追加选项 `item` 为例，在贪婪模式下，`--item abc` 报告值非法，而 `--item 1 abc` 得到 `[1]` 和位置参数 `abc`。若停止追加的参数单元具有未知选项形态，常规识别仍会报告 `UnknownOption`。

显式绑定只取得一个值：若整数追加选项 `item` 的短名为 `i`，贪婪模式下，`--item 1 2` 可以得到 `[1,2]`，但 `--item=1 2` 和 `-i1 2` 都得到 `[1]`，并留下位置参数 `2`。

### 5.5 选项形态值与名称冲突

在待值状态下，未注册的 `-1`、`-Xmx1g`、`--unknown` 可以交给值解析器；在常规识别中，它们具有选项形态，未命中注册表必须报告未知选项。

若注册了短名 `1`，`--count -1` 不会把 `-1` 当负数值：`-1` 被识别为已注册选项，`count` 因无裸用默认值而报告缺值。此时可写 `--count=-1` 或 `-c-1`。

显式绑定绕过下一参数单元的识别判断。长选项可用 `--name=--help` 传入与选项形态相同的值；未设置裸用默认值的短选项可用 `-n--help`。带裸用默认值的短选项不支持这种粘连取值，应使用其长名等号形式。

独立的 `=v` 没有选项前缀：可被待值选项接收，或作为位置参数。`--=v` 则按长选项语法处理，因没有合法注册名而报告 `UnknownOption`，并提示选项名为空。

## 6 值解析与校验

### 6.1 值解析契约

一次值解析按以下顺序执行：保留 `raw`，调用可选的 `normalize(raw)`，再将归一化后的字符串交给 `parse`。未配置归一化时，直接解析 `raw`。

值解析器必须通过明确的成功或失败状态返回结果，不得把结果值的真值作为成功标志。归一化与解析必须确定、无输入消费等副作用；正常的值域拒绝应返回失败，不应通过未约定的异常表达。回调自身的程序异常属于实现或规格错误，不得自动伪装成用户输入错误。

扫描器对一次消费尝试应只进行一次归一化和解析，并保存成功结果供写入使用，避免“先探测、写入时再解析”。失败但未消费的参数单元可以继续作为另一个选项或位置参数处理。

### 6.2 常见值解析器

解析核心没有内置的字符串、整数或布尔选项类型。以下是值解析器实例，具体范围由规格作者声明：

| 值解析器 | 接受规则                                                                     | 示例                                     |
| -------- | ---------------------------------------------------------------------------- | ---------------------------------------- |
| 字符串   | 接受任意字符串，返回传入该解析函数的字符串                                   | 空串、`a=b`、`--help` 均可作为值         |
| 整数     | 先匹配 `^[+-]?\d+$`，再转换并检查目标整数范围                                | `-1` 成功；`0.5`、`1e9` 失败             |
| 布尔值   | `true`、`1`、`yes`、`on` 返回 `true`；`false`、`0`、`no`、`off` 返回 `false` | 默认仅接受表中拼写；大小写处理需显式配置 |
| 枚举     | 与声明的合法成员集合匹配                                                     | `{auto, always, never}`                  |

布尔值解析器不自动赋予裸用行为。只有设置了 `defaultWhenBare`，某次不带值的出现才可以使用默认值。相反，裸用行为也不要求解析值为布尔类型。

### 6.3 联合解析器

联合解析器按声明顺序尝试多个子解析器，采用首个成功结果；全部失败时，报告所有候选值域。子域不必互斥，顺序决定重叠输入的解释。

例如，`threshold` 的值域为“整数，或 `auto`、`unbounded`”：

```text
parse("5")         → 整数解析成功 → 5
parse("auto")      → 整数解析失败 → 枚举匹配成功 → "auto"
parse("0.5")       → 全部失败 → InvalidValue
```

归一化在进入联合解析器前执行。组合器调用各子解析器时，如子解析器还声明了自己的归一化，则按各自接口执行；规格作者必须明确这些变换的先后关系。不得假定“首个成功”意味着其他分支一定失败。

### 6.4 跨选项校验

互斥、依赖和多个值之间的静态约束，可以在成功生成解析结果后由校验组件执行。需要当前文件、服务能力或运行状态才能判断的条件，由业务层处理。帮助与版本输出也由调用方控制；扫描器把 `--help`、`--version` 当作普通的已注册选项。

## 7 默认值与必填及重复规则

### 7.1 单次出现与默认值

| 输入状态                     | 行为                                        |
| ---------------------------- | ------------------------------------------- |
| 某次出现成功解析并取得显式值 | 使用解析值，不使用裸用默认值                |
| 某次出现按扫描规则进入结算   | 有裸用默认值则使用，否则报告 `MissingValue` |
| 整个选项未出现               | 先检查必填约束，再按重复策略处理缺席默认值  |

`defaultWhenBare` 和 `defaultWhenAbsent` 可以同时设置。例如，`color` 的缺席默认值为 `auto`，裸用默认值为 `always`：不提供选项时得到 `auto`，只写 `--color` 时得到 `always`，写 `--color=never` 时得到 `never`。

裸用默认值和缺席默认值均没有对应的用户原始值字符串。使用默认值不产生新的选项出现；使用缺席默认值也不将选项标记为已出现。

### 7.2 重复策略

| `repeat` | 单次出现可取得的值数量       | 多次出现的处理                           | 未出现时的结果               |
| -------- | ---------------------------- | ---------------------------------------- | ---------------------------- |
| `last`   | 一个，来自显式值或裸用默认值 | 后一次出现的值覆盖前一次                 | 缺席默认值；未设置则为未提供 |
| `append` | 默认一个；贪婪分离式可以多个 | 按输入顺序追加所有值                     | `[]`                         |
| `error`  | 一个，来自显式值或裸用默认值 | 识别到第二次出现时报告 `DuplicateOption` | 缺席默认值；未设置则为未提供 |

`last` 允许接收多次出现，只在最终结果中保留最后一个值，不能解释为“整个输入最多只能提供一个值”。`error` 限制的是选项出现次数，不会通过一次贪婪扫描制造重复错误。

`append` 的列表记录已接收的值，长度不代表出现次数。例如，整数追加选项的输入 `--item 1 2` 在贪婪模式下出现一次，但贡献两个值。裸出现时，裸用默认值也作为一个值追加。

为沿用既有规则，`append` 未出现时固定返回 `[]`，不使用 `defaultWhenAbsent`；该字段仅对 `last` 和 `error` 生效。规格作者应省略追加选项上不生效的缺席默认值。若业务需要缺席时的非空初始集合，由调用方根据 `provided` 或结果列表处理。

### 7.3 必填检查与收尾

`required=true` 要求用户显式提供选项，不要求一定使用带值形式。只要允许裸用默认值，裸出现也满足必填约束。

扫描结束后，按以下顺序处理：结算尚未取得值的待值选项；按选项注册顺序检查必填项；填充缺席默认值或追加选项的空列表。缺席默认值不得使必填检查通过，本规范在构建期禁止同时配置二者。

## 8 解析结果与错误

### 8.1 成功结果

成功结果必须提供选项的最终值、是否出现和对应的原始值信息。实现应保留出现历史、值来源和参数位置，支持诊断与调用方的后续约束检查；这些推荐信息可以通过附加接口暴露。具体容器形式可以不同：

| 信息       | 要求                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 结果值     | 以规范长名标识选项；`last`、`error` 返回 `T` 或未提供标记，`append` 返回 `T[]`               |
| `provided` | 每个选项是否实际出现；不得由结果值是否等于默认值推断                                         |
| 出现记录   | 应保留输入顺序、逻辑选项、实际长名或短名拼写、参数单元下标以及短簇内的字符位置               |
| 值记录     | 最终保留的解析值必须保存对应的原始值信息；应另外记录每次出现接收的值、来源和适用时的归一化值 |
| 位置参数   | 保留原始字符串和输入顺序；应保留参数单元下标，供位置约束检查使用                             |

记录值来源时，至少区分“等号绑定”“短选项粘连”“分离式值”“裸用默认值”，并为缺席默认值使用独立的来源标记。缺席默认值也可由 `provided=false` 和规格中的默认值配置判断。默认值记录的 `raw` 必须为 `null` 或明确的无原始值标记，不得伪造输入字符串。

若接口暴露完整出现记录，`last` 覆盖旧结果不得删除该历史。长名与短名指向同一选项；短簇中的多个成员可以具有相同的参数单元下标，但各自是独立的出现记录。

“未提供”必须与合法的 `false`、`0`、空串以及合法的 `undefined` 值区分。可以通过独立标记或值字段存在性表达；不得要求调用方依靠真值判断。

### 8.2 错误类别

| 错误              | 触发条件                                                       |
| ----------------- | -------------------------------------------------------------- |
| `UnknownOption`   | 常规识别中，长名或扫描到的短名未注册，包括长名为空             |
| `MissingValue`    | 尚未取得值的出现需要结算，但没有裸用默认值                     |
| `InvalidValue`    | 显式绑定的值解析失败，或无裸用默认值的首个分离式候选值解析失败 |
| `DuplicateOption` | `repeat=error`，识别到该选项的第二次出现                       |
| `MissingRequired` | 收尾时必填选项没有显式出现                                     |

以上均为命令行用法错误。选项规格错误、回调程序异常和业务执行期错误必须与这些类别区分。

解析采用**遇错即停**的协议：失败时返回或抛出错误，不承诺提供完整的成功结果。调试信息可以包含已处理的局部记录，但调用方不得将其作为成功解析结果使用。因此，`--name -- value` 的规范结果是 `MissingValue`，不同时承诺返回位置参数 `value`。

### 8.3 错误优先级

同一处理点按以下顺序判定：

1. 先处理已有待值状态。因此，`--name --help` 先报告 `name` 缺值。
2. 常规识别先查注册表，再检查该逻辑选项的重复限制。
3. 已知选项若违反 `repeat=error`，在处理其值之前报告重复错误。
4. 输入结束先结算待值状态，再按注册顺序报告首个缺席必填项。

后续贪婪追加尝试的解析失败只是停止条件；其参数单元回到常规识别后，仍按相应规则处理。

### 8.4 诊断信息

错误应包含错误类别、逻辑选项名、相关原始参数单元及其下标。值非法时应说明预期值域，联合解析器应列出全部候选域。

因下一参数单元被识别为已注册选项而报告缺值时，必须给出可用的显式绑定提示。例如：

```text
错误：选项 --name 缺少值。
原因：下一参数单元 "--help" 被识别为已注册选项。
提示：若要把它作为值传入，请使用 --name=--help。
```

若存在适用的短名，可以同时提示 `-n--help`。不得为带裸用默认值的短选项推荐粘连取值。诊断中展示用户输入时应进行适合输出介质的转义，避免不可见字符掩盖实际内容。

## 9 扫描器参考伪代码

下面按索引扫描 `argv`。省略的配置字段和重复策略先补为各自默认值。`beginOccurrence` 查重复限制并建立出现记录；`decodeOnce` 在值解析结果上附带归一化后的字符串；`emit` 接收已经解析好的值或类型化默认值，保存来源并按重复策略归约，不得再次解析原始值。`finish` 仅结束本次出现，不补值。

```text
scan(argv, registry, config):
  i = 0
  pending = null
  positionals = []

  while i < len(argv):
    t = argv[i]

    if pending != null:
      o = pending.option

      if t == "--" or isRegisteredOption(t):
        settle(pending)
        pending = null
        continue                     # 当前 t 尚未消费

      if not config.greedy and hasBareDefault(o):
        settle(pending)
        pending = null
        continue

      r = decodeOnce(o, t)           # normalize 后 parse，保存结果
      if not r.ok:
        if hasBareDefault(o):
          settle(pending)
          pending = null
          continue
        raise InvalidValue(o, t, i)

      emit(pending, r.value, raw=t, normalized=r.normalized,
           source="separated", index=i)
      i += 1

      if config.greedy and o.repeat == "append":
        while i < len(argv):
          u = argv[i]
          if u == "--" or isRegisteredOption(u):
            break
          nextResult = decodeOnce(o, u)
          if not nextResult.ok:
            break                    # 结束追加，不报告 InvalidValue
          emit(pending, nextResult.value, raw=u,
               normalized=nextResult.normalized, source="separated", index=i)
          i += 1

      finish(pending)
      pending = null
      continue

    if t == "--":
      for k in i + 1 .. len(argv) - 1:
        positionals.append({raw: argv[k], index: k})
      i = len(argv)
      break

    if t starts with "--":
      name, raw, attached = splitLongAtFirstEquals(t)
      o = lookupLong(name) or raise UnknownOption(t, i)
      occurrence = beginOccurrence(o, spelling="--" + name,
                                   optionToken=t, index=i)
      if attached:
        r = decodeOnce(o, raw)
        if not r.ok: raise InvalidValue(o, raw, i)
        emit(occurrence, r.value, raw=raw, normalized=r.normalized,
             source="equals", index=i)
        finish(occurrence)
      else:
        pending = occurrence
      i += 1
      continue

    if t starts with "-" and t != "-":
      chars = codepoints(t after first "-")
      for j in 0 .. len(chars) - 1:
        o = lookupShort(chars[j]) or raise UnknownOption(t, i, j)
        occurrence = beginOccurrence(o, spelling="-" + chars[j],
                                     optionToken=t, index=i, clusterPosition=j)
        rest = join(chars[j + 1:])

        if hasBareDefault(o) and rest != "":
          emit(occurrence, o.defaultWhenBare,
               raw=null, source="bare-default")
          finish(occurrence)
          continue                   # 继续扫描本簇

        if rest == "":
          pending = occurrence       # 包括处于簇末尾的裸用选项
        else:
          r = decodeOnce(o, rest)
          if not r.ok: raise InvalidValue(o, rest, i)
          emit(occurrence, r.value, raw=rest, normalized=r.normalized,
               source="attached", index=i)
          finish(occurrence)
        break
      i += 1
      continue

    positionals.append({raw: t, index: i})
    i += 1

  if pending != null:
    settle(pending)
  checkRequiredInRegistrationOrder()
  fillAbsentValues()
  return successfulResult()

settle(occurrence):
  if not hasBareDefault(occurrence.option):
    raise MissingValue(occurrence.option)
  emit(occurrence, occurrence.option.defaultWhenBare,
       raw=null, source="bare-default")
  finish(occurrence)
```

`isRegisteredOption` 必须遵循第 5 节规则。上述所有辅助过程共享同一注册表、出现记录和错误上下文；`settle` 报缺值时应能取得触发结算的参数单元，以生成诊断提示。

## 10 实现约束

注册表和以选项名为键的结果容器必须使用安全的键存储与查询方式。在 JavaScript 中，可以使用 `Map` 或无原型对象；普通对象的查询必须检查自有属性，不得把原型链上的值视为已注册选项。

如果结果要写入或合并到普通对象，必须显式处理 `__proto__`、`constructor`、`prototype` 等危险名称。可以在构建期拒绝这些名称，或采用不会触发原型操作的安全存储和导出方式；不得先接受输入，再静默丢弃结果。

解析器必须保留归一化前的原始值。重复调用不得复用并修改上一次解析的追加列表；类型化默认值若为可变对象，其复制或只读约定应在具体接口中明确，解析过程不得擅自修改规格中的默认值。

实现不得使用真值判断替代解析成功判断、默认值存在性判断或结果是否提供的判断。短选项遍历、短名长度校验及错误位置计算必须采用一致的字符单位。

### 11.1 基准选项规格

### 11.4 默认值与重复及冲突检查

| 输入与规格变体                                       | 结果                                                  |
| ---------------------------------------------------- | ----------------------------------------------------- |
| `--name alice --name bob`                            | `name="bob"`，出现次数为二                            |
| `--item=1 -i 2`                                      | `item=[1,2]`，出现次数为二                            |
| `--name alice -n bob`，`name.repeat=error`           | `DuplicateOption`                                     |
| `--count 1 -c abc`，`count.repeat=error`             | `DuplicateOption`，先于第二次值解析                   |
| `--count 1 2`，`count.repeat=error` 且 `greedy=true` | `count=1`，位置参数 `["2"]`，不因第二个数字报重复     |
| 空输入，`color.defaultWhenAbsent="auto"`             | `color="auto"`，`provided=false`                      |
| `--color`，同时设置上述缺席默认值                    | `color="always"`，`provided=true`                     |
| 空输入，`item.defaultWhenAbsent=9`                   | `item=[]`，`provided=false`；追加选项不使用缺席默认值 |
| `--item`，`item.defaultWhenBare=0`                   | `item=[0]`，`provided=true`                           |
| `--enabled`，`enabled.defaultWhenBare=false`         | `enabled=false`，`provided=true`                      |
| 空输入，`color.required=true`                        | `MissingRequired`                                     |
| `--color`，`color.required=true`                     | `color="always"`，满足必填要求                        |
| `--count -1`，额外注册短名 `1`                       | `MissingValue`，`-1` 被识别为已注册选项               |
| `--count=-1`，额外注册短名 `1`                       | `count=-1`                                            |
| 注册 `required=true` 且设置缺席默认值                | 构建期选项规格错误，不进入输入扫描                    |

实现的一致性检查应覆盖以上行为，并补充：默认值为 `0` 或空串；布尔解析成功返回 `false`；联合解析器的重叠分支顺序；归一化前后原始值保留；安全查表；Unicode 短名；重复解析调用之间的列表隔离。

分离式与显式绑定只在适用条件相同时比较，不能要求所有形式始终等价。尤其需要分别验证裸用选项和贪婪追加选项的绑定差异。

## 附录 A 设计取舍

### A1 规格驱动与值绑定

字符串本身不足以表达选项的合法值域和默认行为。选项规格提供这些信息，解析核心统一执行机制；无需为布尔值、枚举值或帮助选项添加专门的扫描分支。

接口不单独暴露 `arity` 字段，但取值数量并未消失：它由裸用默认值、绑定形式、`greedy` 和 `repeat` 共同决定。实现和说明仍需明确单次出现可以取得多少值。

### A2 显式绑定与名称冲突

分离式取值优先识别已注册选项，避免将用户输入的后续选项静默消费为前一个选项的值。代价是新增注册名可能改变已有命令的解释；例如，注册 `json` 后，`--name --json` 不再把第二项作为字符串值。

长选项等号形式提供不依赖下一参数单元识别的传值方式。由于每个选项都有长名，任何被值解析器接受的原始字符串，包括空串、`--` 和其他选项形态，都可以通过长名等号形式表达。短名粘连仅适用于未设置裸用默认值的选项，不承担所有选项的通用传值保证。

### A3 严格识别与位置参数

常规识别中，未知选项形态报告错误；遇到首个位置参数后继续识别选项。用户要传入以 `-` 开头的位置参数时，可以用独立 `--` 终止选项识别。

独立 `--` 具有明确的语法作用；其触发的待值结算复用统一逻辑。无需为“带默认值时遇到终止符”单独规定另一套取值规则。

### A4 裸用默认值与短选项簇

不使用 `parse(余串)` 猜测短选项簇是否应改作粘连值。否则，余串同时能解释为合法值和多个短名时，解释将依赖值域的偶然重叠。统一按裸用默认值的存在性决定簇内行为，并让末尾选项进入待值状态。

## 附录 B 与原稿的主要差异

本次重整以《CLI 键值解析规范（v2）》为主要依据，以另一份未标版本的旧稿核对设计沿革。原稿文件保持不变。以下记录区分沿用的规则与本次修正，不作为额外的输入语法。

| 项目               | 本稿处理                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 标题与范围         | 改为选项与参数解析，明确输入为不含程序名的 `argv`                                                                            |
| 类型术语           | 将描述并集的“交叉类型”统一为联合解析器；首个成功只保证选择确定，不保证子域互斥                                               |
| 状态模型           | 区分选项整体是否出现与每次出现是否带值，单独记录出现次数和值数量                                                             |
| 默认消费           | 沿用 v2：有裸用默认值时，`greedy=false` 不消费下一参数单元                                                                   |
| 短选项冲突修复     | 带裸用默认值的短选项处于簇中间时用默认值，处于末尾时进入待值状态，使分离式贪婪取值与正文承诺一致                             |
| 显式绑定边界       | 明确等号和粘连只取得一个值，不延续贪婪追加；沿用原伪代码行为                                                                 |
| 默认值参与决策     | 删除“不参与分词决策”的说法，明确其对消费和短簇扫描的影响                                                                     |
| 追加列表           | 保留缺席返回 `[]`，改为用接收的值解释列表长度；明确追加选项不使用缺席默认值                                                  |
| 数字示例           | 修正整数解析器接受 `0.5` 的错误，不放宽整数值域                                                                              |
| 空名称与普通字符串 | 独立 `=v` 按普通参数处理；`--=v` 作为无合法注册名的选项报告错误                                                              |
| 终止符             | 将“`--` 不得当值”限定为独立参数单元，保留显式绑定字符串 `--` 的能力                                                          |
| 错误协议           | 明确遇错即停、局部优先级和必填检查顺序；不承诺失败后的完整位置参数                                                           |
| 值解析契约         | 明确成功状态、归一化顺序、类型化默认值的责任，以及保留解析结果避免二次解析                                                   |
| 结果与安全         | 保留最终值、出现标记与原始值的必需输出，新增出现历史、值来源和位置等推荐信息；补充安全查表要求，不得静默过滤已接受的选项结果 |
| 行文与结构         | 统一术语和规范用语，将设计理由与历史说明移至附录，重建行为表和章节引用                                                       |
