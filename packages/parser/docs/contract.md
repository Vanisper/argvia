# 解析契约

`@argvia/parser` 为已确定作用范围的 argv 提供选项识别、值绑定、来源记录与必填检查。完整解析和分阶段解析共用以下行为。

## 输入

输入是已分词、已确定选项作用范围的 `readonly string[]`，由待解析的参数组成，解释器、脚本路径和程序名应在传入前移除。每个元素作为一个参数处理，空字符串、空格和引号字符保持原样。

## 值协议

`ValueParser<T>` 的 `normalize` 和 `parse` 依次解释字符串值。成功和失败使用显式的 `ok` 判别；成功值可以是 `false`、`0`、空串或 `undefined`。每次消费尝试只归一化和解析一次，结果直接用于记录与归约。回调应确定且无副作用，抛出的异常原样传播。

`snapshotValueParser(parser)` 校验并冻结回调引用。`decodeValue(parser, raw)` 执行同一协议并返回 normalized 与解析结果，回调作为独立函数调用。

| 工厂                                   | 值域或组合方式                                                           |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `values.string()`                      | 接受所有字符串，保留空白与空串                                           |
| `values.integer({ min?, max? })`       | 接受可带正负号的十进制安全整数，可用闭区间限制值域                       |
| `values.boolean()`                     | 大小写敏感地接受 `true/1/yes/on` 和 `false/0/no/off`                     |
| `values.enumeration(choices)`          | 从非空字符串候选列表中精确匹配，保留成员联合类型                         |
| `values.union(parsers)`                | 从非空解析器列表中按声明顺序选择首个成功分支；全部失败时合并候选值域说明 |
| `values.normalized(parser, normalize)` | 先应用外层归一化，再执行子解析器已有的归一化与解析                       |

记录中的 normalized 表示选项值解析器这一层的归一化结果。需要统一记录的变换应通过 `values.normalized(values.union(...), normalize)` 放在联合外层；各分支内部的变换由该分支自行处理。

## 选项定义

每份定义包含一个长名、可选的一个 Unicode 码点短名、值解析器，以及裸用默认值、缺席默认值、必填标记与重复策略。

- 名称大小写敏感；长名不得为空、以 `-` 开头或含 `=`；短名不得为 `-`；同类名称不得重复
- 默认值已经属于目标值域，直接保留；字段是否设置依据自有属性，包含显式的 `undefined`
- `required` 要求选项显式出现，允许使用裸用默认值满足要求
- `repeat` 支持 `last`、`append`、`error`，默认 `last`
- `required` 与缺席默认值不能同时设置
- `append` 与缺席默认值不能同时设置；创建时拒绝此无效组合

注册时检查这些约束并创建定义与回调的快照。默认对象保持原引用，调用者应将其视为只读。默认值的值域合法性由规格作者保证，例如 `values.integer({ min: 1 })` 的数值类型仍允许声明默认值 `0`，运行时会直接采用它。

## 识别与消费

| 输入形式                   | 行为                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `--name=value`             | 在第一个等号处分割，余串可为空或包含其他等号；显式取得一个值                          |
| `--name value`、`-n value` | 根据注册表、裸用默认值和贪婪配置判断分离值的归属                                      |
| `-nvalue`                  | `n` 没有裸用默认值时，余串整体是一个值，包含其中的 `=`                                |
| `-abc`                     | 按 Unicode 码点扫描；有裸用默认值的中间成员使用默认值，无裸用默认值的成员消费全部余串 |
| `-`                        | 位置参数，或被待值选项接收为值                                                        |
| 独立 `--`                  | 先结算待值选项，再将其后全部输入作为位置参数；终止符自身不进入位置参数                |

分离值判断优先识别独立 `--` 与已注册选项。短簇只要首个短名已注册，就会阻止前一个选项消费；簇中后续未知成员由常规扫描报告。

未注册的 `-1`、`-value`、`--unknown` 可以成为待值选项的候选值；回到常规识别时，未知选项形态仍报错。遇到位置参数后继续识别后面的选项。显式绑定确定值的归属，例如 `--name=--verbose` 将 `--verbose` 作为字符串值。

默认 `greedy=false`：有裸用默认值的选项不消费下一元素，其余选项尝试一个分离值。`greedy=true`：裸用选项也尝试分离值；只有 `append` 会在首值成功后继续消费可解析候选值。

首值失败且没有裸用默认值时报 `InvalidValue`；有裸用默认值则结算并重新识别该元素。追加的后续候选失败只结束追加，再重新识别该元素。显式绑定每次取得一个值，随后返回常规识别。

## 归约与来源

`last` 保留最后一次贡献，`append` 按顺序收集值，`error` 在识别到第二次出现时立即拒绝，不调用第二次的值回调。缺席的追加选项返回新建的空列表。

结果同时保留：

- `values`：归约后的值；缺席且没有默认值的非追加选项省略该键
- `provided`：是否显式出现，和结果值的真值无关
- `records`：归约后保留的值贡献，包含缺席默认值
- `occurrences`：所有显式出现的完整历史，包含被 `last` 覆盖的贡献
- `positionals` 与 `positionalTokens`：位置参数及原始下标
- `terminatorIndex`：独立 `--` 的下标，未出现则为 `null`

每份值记录包含解析值、原始值、归一化值、来源和值下标。来源区分等号、短粘连、分离值、裸用默认值、缺席默认值。默认值的 raw、normalized 与值下标均为 `null`。

一次贪婪追加可以产生多个值，但只形成一次出现。短簇中各成员共享 token 下标，另有按码点计算的簇内位置。

合法的 `undefined` 通过 `Object.hasOwn(result.values, name)` 或对应 `records` 与缺席区分。名称容器使用无原型对象；`__proto__`、`constructor` 等名称按普通键处理。结果容器与记录浅冻结，每次调用拥有独立的追加列表。

## 准备与完成

`createParser(options, config?)` 创建解析器，`greedy` 在创建时设置。

1. `prepare(argv)` 完成识别、值解析、默认值、重复归约和来源记录，暂不检查必填选项
2. `complete(prepared)` 只接受当前实例创建的准备结果，按注册顺序检查显式必填要求，返回类型收窄后的完整结果
3. `parse(argv)` 等价于 `complete(prepare(argv))`

准备态中的必填字段仍保留缺席可能。`prepare([])` 可以生成含缺席必填项的结果，对它调用 `complete` 会抛出 `MissingRequired`。成功的完成结果被缓存，重复完成直接返回该结果；失败时再次检查必填项。完成阶段复用准备阶段的值与来源，值回调仅在准备阶段执行。不同解析调用各自拥有状态。

## 错误与优先级

用法错误以 `ParseError.code` 区分 `UnknownOption`、`MissingValue`、`InvalidValue`、`DuplicateOption`、`MissingRequired`。错误带有相关选项、token 和下标；非法值还带有 expected/reason。缺值由后续已注册选项触发时，提供长名等号绑定提示。

遇错即停并抛出错误。先结算待值，再识别当前 token；先查注册表，再检查重复；重复先于第二次值解析；结束输入先处理缺值，再由完成阶段按注册顺序检查必填项。

定义错误属于 `OptionSpecError`，值回调返回协议错误属于 `ValueParserContractError`；回调自己抛出的异常保持原样。这些错误与用法错误分别处理。
