# 第一轮解析契约

本轮实现 `@argvia/parser` 的独立解析与准备、完成流程。以归档《CLI 选项与参数解析规范》中的识别和绑定算法为研究依据，采用下列明确行为；不承诺历史包的 API 兼容。包继续保持 private，接口形式将在实际使用中评估。

## 输入与职责

输入是已分词、已确定作用范围的 `readonly string[]`，不包含解释器、脚本路径或程序名。parser 不执行 shell 分词，不处理命令树，不读进程全局，不执行帮助、版本或业务操作。空字符串、空格和引号字符按数组中的原样处理。

值解释由 `ValueParser<T>` 的 `normalize` 和 `parse` 提供。成功和失败使用显式的 `ok` 判别；成功值可以是 `false`、`0`、空串或 `undefined`。每次消费尝试只归一化和解析一次，结果直接用于记录与归约。回调异常原样传播，不伪装为命令行用法错误。

公开的 `snapshotValueParser(parser)` 校验并冻结回调引用，`decodeValue(parser, raw)` 统一执行协议并返回 normalized 与解析结果。core 的命名位置参数使用这两个入口，复用同一份协议校验；调用者不需要深导入内部模块。

联合值解析器按声明顺序选择首个成功分支。记录中的 normalized 表示选项值解析器这一层的归一化结果；联合内部各分支自己的变换不覆盖它。需要统一记录的变换应通过 `values.normalized(values.union(...), normalize)` 放在外层。

## 选项定义

每份定义包含一个长名、可选的一个 Unicode 码点短名、值解析器，以及裸用默认值、缺席默认值、必填标记与重复策略。

- 名称大小写敏感；长名不得为空、以 `-` 开头或含 `=`；短名不得为 `-`；同类名称不得重复
- 默认值已经是解析后的类型，不再经过值回调；字段是否设置依据自有属性，包含显式的 `undefined`
- `required` 要求选项显式出现，允许使用裸用默认值满足要求
- `repeat` 支持 `last`、`append`、`error`，默认 `last`
- `required` 与缺席默认值不能同时设置
- `append` 与缺席默认值不能同时设置；这是相对于归档规范的明确调整，拒绝无效组合，不静默忽略字段

注册时检查这些约束并创建定义与回调的快照。类型化默认对象仍由调用者持有；parser 不深复制或修改对象，调用者应将其视为只读。

## 识别与消费

| 输入形式                   | 行为                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `--name=value`             | 在第一个等号处分割，余串可为空或包含其他等号；显式取得一个值                          |
| `--name value`、`-n value` | 根据注册表、裸用默认值和贪婪配置判断分离值的归属                                      |
| `-nvalue`                  | `n` 没有裸用默认值时，余串整体是一个值；不剥离 `=`                                    |
| `-abc`                     | 按 Unicode 码点扫描；有裸用默认值的中间成员使用默认值，无裸用默认值的成员消费全部余串 |
| `-`                        | 位置参数，或被待值选项接收为值                                                        |
| 独立 `--`                  | 先结算待值选项，再将其后全部输入作为位置参数；终止符自身不进入位置参数                |

分离值判断优先识别独立 `--` 与已注册选项。短簇只要首个短名已注册，就会阻止前一个选项消费；簇中后续未知成员由常规扫描报告。

未注册的 `-1`、`-Xmx1g`、`--unknown` 可以成为待值选项的候选值；回到常规识别时，未知选项形态仍报错。遇到位置参数后继续识别后面的选项。显式绑定绕过名称冲突，例如 `--name=--help` 是字符串值。

默认 `greedy=false`：有裸用默认值的选项不消费下一元素，其余选项尝试一个分离值。`greedy=true`：裸用选项也尝试分离值；只有 `append` 会在首值成功后继续消费可解析候选值。

首值失败且没有裸用默认值时报 `InvalidValue`；有裸用默认值则结算并重新识别该元素。追加的后续候选失败只结束追加，再重新识别该元素。显式绑定始终只取得一个值，不延续贪婪追加。

## 归约与来源

`last` 保留最后一次贡献，`append` 按顺序收集值，`error` 在识别到第二次出现时立即拒绝，不调用第二次的值回调。缺席的追加选项返回新建的空列表。

结果同时保留：

- `values`：归约后的值；缺席且没有默认值的非追加选项省略该键
- `provided`：是否显式出现，和结果值的真值无关
- `records`：归约后保留的值贡献，包含缺席默认值
- `occurrences`：所有显式出现的完整历史，包含被 `last` 覆盖的贡献
- `positionals` 与 `positionalTokens`：位置参数及原始下标
- `terminatorIndex`：独立 `--` 的下标，未出现则为 `null`

每份值记录包含解析值、原始值、归一化值、来源和值下标。来源区分等号、短粘连、分离值、裸用默认值、缺席默认值。默认值的 raw、normalized 与值下标均为 `null`，不伪造输入。

一次贪婪追加可以产生多个值，但只形成一次出现。短簇中各成员共享 token 下标，另有按码点计算的簇内位置。

合法的 `undefined` 通过 `Object.hasOwn(result.values, name)` 或对应 `records` 与缺席区分。名称容器使用无原型对象；`__proto__`、`constructor` 等名称按普通键处理。结果容器与记录浅冻结，不共享可变的追加列表。

## 准备与完成

`createParser(options, config?)` 创建解析器，`greedy` 在创建时设置。

1. `prepare(argv)` 完成识别、值解析、默认值、重复归约和来源记录，暂不检查必填选项
2. `complete(prepared)` 只接受当前实例创建的准备结果，按注册顺序检查显式必填要求，返回类型收窄后的完整结果
3. `parse(argv)` 等价于 `complete(prepare(argv))`

准备态中的必填字段仍保留缺席可能。完成阶段不重新扫描或调用值回调；重复完成同一准备结果也不重新解析。不同解析调用各自拥有状态。

上层可以在准备成功后依据真实绑定的 help 值选择不调用 `complete`，从而跳过必填检查。这不保证跳过值回调，也不覆盖其他输入错误：`--help --unknown`、非法值后跟 `--help` 仍失败。`--name=--help` 和 `-- --help` 不构成帮助请求。

本轮不提供命令级约束、错误恢复、原始字符串预扫描或完整 core 调用流程。

## 错误与优先级

用法错误以 `ParseError.code` 区分 `UnknownOption`、`MissingValue`、`InvalidValue`、`DuplicateOption`、`MissingRequired`。错误带有相关选项、token 和下标；非法值还带有 expected/reason。缺值由后续已注册选项触发时，提供长名等号绑定提示。

遇错即停，不返回伪造的完整结果。先结算待值，再识别当前 token；先查注册表，再检查重复；重复先于第二次值解析；结束输入先处理缺值，再由完成阶段按注册顺序检查必填项。

定义错误属于 `OptionSpecError`，值回调返回协议错误属于 `ValueParserContractError`；回调自己抛出的异常保持原样。这些错误与用法错误分别处理。

## 第一轮验收

规范用例覆盖绑定形式、贪婪矩阵、默认值与重复策略、错误优先级、Unicode、安全键、来源和单次回调。类型验证覆盖准备态缺席、完成态必填、默认值类型、追加类型与动态定义的保守推导。再通过构建产物验证独立导入及 core 后续所需的准备、完成组合。
