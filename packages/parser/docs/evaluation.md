# 解析策略与算法

parser 使用注册表驱动的确定性单向扫描，并以局部值解析试探决定分离值归属。它适用于已分词、已确定选项作用范围的 argv。行为规则见[解析契约](contract.md)。

## 执行结构

`createParser` 检查规格，将长短名编译为注册表，保存定义与回调快照。每次 `prepare` 复制输入数组并创建独立状态，以一个游标扫描。当前选项试探下一个元素，成功后推进游标并直接保留解析结果；失败时按规则报错，或将尚未消费的元素交回主扫描。

消费决策只依赖当前选项、候选元素及已注册名称。贪婪追加停止时，已经取得的值保持不变，扫描继续处理尚未消费的元素。

扫描结束后生成值、显式提供状态、归约记录和出现历史。`complete` 验证准备结果的实例归属，检查选项必填要求并缓存成功结果，直接复用准备阶段的值与来源。

| 阶段     | 实现                                           | 关键行为                                  |
| -------- | ---------------------------------------------- | ----------------------------------------- |
| 注册     | [parser.ts](../src/parser.ts)，`createParser`  | 名称、默认值冲突、重复策略与回调快照      |
| 边界识别 | [parser.ts](../src/parser.ts)，`isRegistered`  | 终止符与已注册选项优先于分离值            |
| 分离值   | [parser.ts](../src/parser.ts)，`following`     | 根据裸用默认值、greedy 与 repeat 决定消费 |
| 值归约   | [parser.ts](../src/parser.ts)，`decode/retain` | 复用成功值；按 last、append、error 归约   |
| 完成     | [parser.ts](../src/parser.ts)，`complete`      | 实例归属、必填顺序与成功缓存              |
| 值协议   | [values.ts](../src/values.ts)                  | 显式成功或拒绝、归一化、联合及异常传播    |

## 不变量

1. 成功结果中的每个输入元素属于选项出现、分离值、位置参数或终止符。短簇的多个出现共享元素下标；显式绑定的值与选项共享下标。
2. 游标单向推进。接受候选元素时推进游标；拒绝候选元素时保留游标，由主扫描继续处理该元素。
3. 独立 `--` 和已注册选项阻止分离值消费。短簇边界只检查首成员，完整簇由主扫描逐项验证。
4. 每次消费尝试执行一次该层归一化与解析，成功结果直接进入记录。联合值解析器可按顺序尝试多个子解析器。
5. 显式出现由 provided 记录，独立于结果值及其来源。false、0、空串和合法 undefined 都可以是显式提供的值。
6. 完成阶段依据已有的显式出现记录检查必填，只接受本实例产生的准备结果。
7. 每次调用拥有独立的计数、列表和游标。容器浅冻结，调用者的对象值保持引用。

## 复杂度

记 `M` 为选项数，`L` 为注册名称字符总量，`N` 为输入元素数，`B` 为输入字符总量，`H` 为显式出现数，`V` 为成功值贡献数，`C` 为全部值回调的执行成本。以下使用 Map 的通常平均查找成本：

| 操作                | 时间               | 空间与注意点                                                         |
| ------------------- | ------------------ | -------------------------------------------------------------------- |
| 创建解析器          | `O(M + L)`         | 注册表与规格快照 `O(M + L)`                                          |
| 一次 prepare        | `O(M + N + B + C)` | 容器约 `O(M + N + H + V)`，字符串处理另计至 `O(B)`，回调产生的值另计 |
| 首次成功 complete   | `O(M)`             | 复用冻结字段与来源记录                                               |
| 重复成功 complete   | `O(1)`             | 返回缓存结果                                                         |
| 必填失败的 complete | 最坏 `O(M)`        | parser 不缓存失败，重复调用仍检查必填                                |

扫描成本随输入元素和字符量线性增长。联合候选的数量、顺序及各分支实现决定回调成本 `C`；实际吞吐量需要结合具体值协议与输入规模测量。

使用 last 时，出现记录仍保存被覆盖的贡献，内存随全部出现与值贡献增长。这些记录用于诊断与来源分析。

## 消费取舍

下表假定 name 为字符串、count 为整数、item 为整数 append，三者均无裸用默认值；flag 为裸用默认值 true 的布尔选项。其他配置逐行注明。

| 输入与配置                         | 结果                    | 含义                                         |
| ---------------------------------- | ----------------------- | -------------------------------------------- |
| `--name --unknown`，unknown 未注册 | `name="--unknown"`      | 允许选项形态的字符串值，也可能吸收拼错的名称 |
| `--name --flag`，flag 已注册       | `MissingValue`          | 新增注册项可能改变分离值归属                 |
| `--name=--flag`                    | `name="--flag"`         | 显式绑定消除名称冲突                         |
| `--count -1`，短名 1 未注册        | `count=-1`              | 负数通过相同的候选值规则解析                 |
| `--count -1`，短名 1 已注册        | `MissingValue`          | 可用 `--count=-1` 明确绑定                   |
| `--flag false`，greedy=false       | flag=true，位置值 false | 布尔类型与分离值消费是不同规则               |
| `--flag false`，greedy=true        | flag=false              | greedy 同时影响裸用选项                      |
| `--item 1 bad`，greedy=true        | item=[1]，位置值 bad    | 后续追加失败表示边界                         |
| `--item bad`                       | `InvalidValue`          | 无裸用默认值时，首值失败是输入错误           |
| `--item=1 2`，greedy=true          | item=[1]，位置值 2      | 显式绑定一次只贡献一个值                     |
| `--name --`                        | `MissingValue`          | 独立终止符不作为分离值                       |

默认使用 `greedy=false`，让分离值消费保持局部。字符串追加在 greedy=true 时会持续接受普通后续文本；预期的位置参数可能因此成为选项值。调用者可以用重复的显式绑定和 `--` 明确边界。
