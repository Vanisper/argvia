# 第二轮单命令契约

本轮解决一个已经选定的命令如何解释输入、响应内建请求并调用 handler。输入仍是不包含程序名的 argv。命令树、路由、共享或继承选项、宿主 I/O、退出状态、配置合并和进程生命周期留待后续用例评估。

## 共同定义

`createCommand` 接收命令名称、描述、业务选项、命名位置参数、handler，以及可选的帮助开关、版本字符串和 parser 配置。

选项直接采用 parser 的 `OptionSpec`，增加 `description`、`valueName` 帮助元数据。帮助与执行共用同一份定义；不会通过执行值回调来猜测合法值域，不序列化任意类型的默认对象。

位置参数声明 `name`、`parse`、可选的 `description`、`required` 和 `variadic`。本轮不支持位置参数默认值或基于其他字段的条件位置语法。

定义和回调在创建时取得快照。外部依赖通过闭包或命令工厂注入，普通入口不读取 Node 或浏览器全局。

## 调用顺序

一次调用严格遵循以下顺序：

1. parser 准备选项输入，进行真实识别、值解析、默认值与重复归约
2. 检查已绑定的帮助、版本请求
3. parser 完成业务选项必填检查
4. 检查位置参数数量，依据声明顺序分配
5. 使用 parser 公开的值协议工具解码位置参数，生成完整命令输入
6. 仅执行入口调用并等待 handler

`parse(argv)` 同步返回 `input`、`help` 或 `version` 请求，不执行 handler。`execute(argv)` 异步返回 `executed`、`help` 或 `version`，内部只走一次上述解析流程。分别调用两个入口是两次独立操作；不要为检查请求先 parse，再将同一 argv 传给 execute。

正常执行结果保留完整 `input` 与 handler 的 `value`，同步、异步返回值均可使用。数字返回值是普通业务值，不自动解释为退出码；core 不自动输出任何结果。

## 帮助与版本

默认启用 `--help/-h`，`help: false` 可关闭。提供 `version` 字符串时启用 `--version/-V`。内建选项与业务长名或短名冲突时拒绝定义，不静默覆盖。关闭相应内建能力后，同名业务选项按普通定义工作。

内建选项复用普通布尔值协议与裸用默认值；仅显式出现且解析值为 true 时产生请求。`--help=false` 不请求帮助；同时请求帮助和版本时，帮助优先。帮助返回冻结的 `HelpDocument`，版本返回声明的字符串。

帮助与版本可以跳过业务必填检查、位置数量检查和全部位置值回调；不能跳过选项的未知、缺值、非法值或重复错误，也不保证跳过选项值回调。`--name=--help`、作为待值字符串被消费的 `--help`、终止符后的 `--help` 均依据真实绑定事实处理，不进行原始数组预扫描。

`command.help` 暴露同一份帮助文档。`renderHelp(document)` 是纯文本格式化函数，不写 stdout，不设置退出码。文档列出选项名称、值标签、描述、必填与重复信息，以及位置参数的顺序和数量形式。

## 命名位置参数

必填参数位于可选参数之前，最多有一个 variadic 参数且必须在末尾。必填 variadic 至少接收一个值；可选 variadic 缺席时得到本次调用独立的空数组。普通可选参数缺席时省略值键，但保留 `provided=false` 与空记录。

位置参数仅消耗 parser 已确定的 `positionalTokens`。先按声明顺序报告缺席必填参数，再检查超额参数，然后依次执行值解析。不会根据某个值解析器是否接受来重新分配，也不会将已被选项消费的值回退或预留给位置参数。

每个候选位置值只执行一次归一化与解析；raw、normalized 和 index 来自原始 argv。合法的 `undefined` 仍有值键、记录和显式提供标记。名称容器使用无原型对象，`__proto__` 等名称按普通键处理。

## 输入与来源

handler 的 `input.options` 是完整业务选项值，`input.arguments` 是命名位置值。它们由声明推导；内部帮助、版本字段不会进入业务值或业务来源记录。动态数组与宽化名称保持保守类型，不虚构字段存在。

`input.source.options` 保留业务选项的解析事实、出现历史和原始坐标，`input.source.arguments` 保留位置值、provided 与记录。便利值与来源中的 values 共用引用。容器、记录和结果浅冻结；值对象本身不深复制或冻结。

## 错误

parser 的用法错误和规格错误继续原样传播。位置用法错误为 `ArgumentError`，通过 `code` 区分 `MissingArgument`、`UnexpectedArgument`、`InvalidArgument`，并保留相关参数名、token、index、expected 与 reason。

命令元数据、名称冲突或位置排列错误为 `CommandSpecError`。值回调的程序异常、协议错误和 handler 异常保持原样，不通过笼统捕获转成用户输入错误。

## 组合验收

jar 入口用必填 jar 位置参数加末尾应用参数，main 入口用必填 `--main` 加全部应用参数。两个独立命令对象验证输入分配与业务闭包；不将 `jar?` 与 main 选择混在一个位置模型中，也不把 Java 运行规则放入 core。

验证同时覆盖无 dist 的工作区检查、测试，以及默认导出条件下构建产物的独立导入和类型消费。
