# 命令组合与调用契约

core 接收不含程序名的 `readonly string[]`，从定义树选择节点、准备选项输入、完成约束检查，并按需调用 handler。所有节点共用 parser 的选项规则与值协议。

## 节点定义

`createCommand` 创建叶子命令，接受名称、可选描述与普通元数据、选项、位置参数、parser 配置及 handler。`createGroup` 创建分组，接受同样的节点元数据、本地选项、parser 配置及已创建的子节点数组。分组没有 handler 或位置参数。

每个子节点以自己的 `name` 参与路径选择。同一分组内名称必须唯一；同一节点可以被多个分组复用。节点来源在组合时检查，不以任意同形对象代替已创建节点。

名称、值标签和位置参数名必须为非空标签，不包含空白、控制字符或尖括号、方括号；节点名称不能以 `-` 开头。长短选项名称还需符合 parser 的定义约束。说明文本可以是普通字符串。

选项增加 `description/valueName` 展示元数据，位置参数增加 `description`。这些字段与解析规则共用一份声明。选项值的结果键为 `long`，位置值的结果键为 `name`。

共享字段采用声明复用，每个节点独立保存规格与回调快照。分组选项只在选中该分组时可见，不向子节点继承。

## 结构化定义

节点公开冻结的 `definition`：

- 共同字段为 `kind`、`name`、可选 `description/metadata`、`options` 和 `parser`。
- 叶子描述含有 `arguments`，分组描述含有递归的 `commands`。
- 规格保存被支持的字段及值回调快照，元数据复制其字段容器；handler 不进入描述。
- `parser` 明示实际配置，未配置 greedy 时为 `false`。

描述读取不执行回调。默认值和元数据中的对象仍为原引用，不深复制或深冻结；值解析器也无法自动转换成可序列化的值域说明。需要枚举候选、示例或其他展示信息时，由应用显式组织元数据。

路径不属于定义。每次调用的 `path` 从入口节点名称开始，包含选中节点前的所有分组与最终节点。

## 显式路由

路由从当前分组读取下一个元素：

1. 输入结束，选中当前分组。
2. 元素以 `-` 开头，包括 `-` 和 `--`，选中当前分组，剩余输入交其 parser。
3. 元素是已声明的子节点名称，消费该名称并进入子节点。
4. 其他元素产生 `UnknownCommand`，保留未知元素的原始下标及当前路径。

到达叶子后立即结束路由，后续全部元素交给叶子的 parser。不会根据位置值或值解析结果重新选择命令，也不会在选项之间继续寻找子命令。输入结束停在分组，不自动选择默认命令。

以下以根 `tool`、分组 `project` 和叶子 `build` 为例，数组均不含程序名：

| argv                                   | 路由与处理                                                |
| -------------------------------------- | --------------------------------------------------------- |
| `[]`                                   | 选中 tool 分组                                            |
| `["project"]`                          | 选中 project 分组                                         |
| `["project", "build", "src"]`          | 选中 build，src 是其输入                                  |
| `["unknown"]`                          | tool 下的 `UnknownCommand`                                |
| `["project", "unknown"]`               | project 下的 `UnknownCommand`，下标为 1                   |
| `["--inspect", "project"]`             | 停在 tool；inspect 必须在 tool 声明，project 不再参与路由 |
| `["--", "project"]`                    | 停在 tool；project 为其位置元素，完成时报告超额位置参数   |
| `["project", "build", "--", "--help"]` | 选中 build；终止符后的 --help 为位置元素                  |

分组的准备结果可以包含尚未检查的位置元素。分组完成时按空位置参数声明校验，因此选项之后留下的子命令文字不会被静默忽略。

## 准备、完成与执行

`node.prepare(argv)` 复制输入，完成路由，然后使用选中节点的 parser 识别、绑定、解析并归约选项。返回节点、路径、准备态选项、来源及 `complete()`。

准备阶段会执行选项值回调；未知选项、缺值、非法值与重复错误即时报告。选项必填检查、位置数量检查和位置值解析在完成阶段执行。

`prepared.complete()` 按以下顺序处理：

1. 检查选项的显式必填要求。
2. 按位置声明顺序检查缺少的必填参数，再检查超额参数。
3. 按固定位置分配解码位置值。
4. 生成完整输入及命令或分组完成结果。

同一准备结果缓存完成阶段的成功或失败。重复完成返回同一结果，或再次抛出同一失败，不重复选项或位置回调。不同 prepare 调用拥有独立状态。

完成结果通过 `input.options`、`input.arguments` 提供便利值，通过 `input.source` 保留来源。命令完成结果提供 `execute()`，每次调用一次 handler 并等待其返回；重复执行不重新解析，也不缓存 handler 的返回值或异常。

节点上的便捷入口遵循同一过程：

- `node.parse(argv)` 等价于 `node.prepare(argv).complete()`。
- `node.execute(argv)` 先完成输入，再执行命令。若完成结果是分组，抛出 `MissingCommand`；选项或位置错误会先报告。

执行结果包含 `kind: "executed"`、名称、定义、路径、完整输入与 `value`。数字、对象或其他返回值均保留业务含义，core 不输出也不设置退出状态。

## 位置参数

必填参数位于可选参数之前，最多有一个 variadic 参数且必须位于末尾。必填 variadic 至少接收一个值，可选 variadic 缺席时得到本次调用独立的空数组。普通可选参数缺席时省略值键，保留 `provided=false` 与空记录。

位置参数只消费 parser 已确定的 `positionalTokens`。不会根据值域接受情况重新分配，不从选项已消费的输入中预留位置值。位置默认值和跨字段条件语法不属于当前规格。

每个候选位置值只执行一次归一化与解析。合法 `undefined` 仍有自有值键、记录和显式提供标记。名称容器采用无原型对象，`__proto__`、`constructor` 按普通键处理。

## 来源坐标

路径消费不会改变调用方看到的坐标。以下字段均相对本次入口收到的完整 argv：出现下标、显式值下标、位置元素下标、终止符下标，以及输入错误的 `index/nextIndex`。默认值的下标保持 `null`，短簇的 `clusterPosition` 仍为簇内码点位置。

直接调用一个叶子时，坐标相对传给该叶子的数组；从根分组调用时，坐标相对传给根的数组。同一节点在不同调用路径下具有不同 path 和坐标，但共用只读定义。

便利值与来源中的 values 共用引用，保留记录与出现历史中同一贡献的关联。容器和记录浅冻结，值对象本身不深复制或冻结。

## 应用控制逻辑

core 不注册 help/version 选项或定义相关结果分支。应用可以在普通元数据中保存版本，声明普通选项，再读取准备结果决定是否完成或执行。

例如，应用读取 `prepared.options.help` 后自行渲染 `prepared.definition`，可以在未提供必填输入时显示内容。该模式依赖成功准备，不自动覆盖路由错误、非法选项值或程序异常。控制逻辑的触发形式、优先级与输出属于应用。

## 错误

| 错误                       | 类别与内容                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------- |
| `RouteError`               | `UnknownCommand` 或 `MissingCommand`，保留路径、可选子命令及适用的 token/index         |
| `ParseError`               | parser 的用法错误，保留类别与原 argv 坐标                                              |
| `ArgumentError`            | `MissingArgument`、`UnexpectedArgument`、`InvalidArgument`，保留参数名、原文与适用坐标 |
| `OptionSpecError`          | 选项规格无效                                                                           |
| `CommandSpecError`         | 节点元数据、子节点组合、位置排列或字段展示规则无效                                     |
| `ValueParserContractError` | 值回调返回协议无效                                                                     |

回调与 handler 自己抛出的异常保持原样，包括它们主动抛出的输入错误对象。库只为自己产生的输入诊断维护坐标，不把程序异常包装成用户输入失败。
